# Пит-радар — контекст для Claude Code

Отвечай пользователю по-русски. Интерфейс приложения тоже на русском.

## Суть

Браузерное приложение для командного картингового марафона на Стайках (Минск): 5 ч, 11:00–16:00, трек 1233 м, круг ~1:04–1:08 на сухом, ~1:14 в дождь. Оператор смотрит его с телефона в боксах.

Задача — знать, какие физические карты быстрые, и видеть, когда быстрый карт уходит в пит-лейн, чтобы заехать за ним.

Регламент, на котором держится логика:
- Номер команды = транспондер, не карт. Карт команды меняется на каждом пите.
- 15 обязательных питов, стинт ≤ 35 мин (от PIT IN до PIT IN), пит ≥ 2 мин, первый пит не раньше 10 мин.
- После PIT IN софт случайно назначает коридор A или B. Команда ставит свой карт в хвост коридора и берёт ПЕРВЫЙ карт этого коридора. Это строгий FIFO постоянной длины.
- При поломке запасной карт выдают на трассе. Красный флаг останавливает время гонки.

## Деплой и рабочий процесс

- Всё приложение — один файл `index.html`, без сборки, без зависимостей кроме CDN (SortableJS 1.15.0 с cdnjs, шрифт Roboto Condensed с Google Fonts).
- Хостится на GitHub Pages из ветки `main`, корень: **https://mixuigi.github.io/best-cart/**. Пуш в `main` → через ~1 мин обновляется на телефоне (обновить страницу).
- Правки часто делаются **прямо во время гонки**. Поэтому:
  - Маленькие точечные коммиты, сразу пуш в `main` (без PR, если пользователь не просит иное).
  - Перед пушем — синтаксическая проверка (ниже). Сломанный JS посреди гонки = белый экран.
  - **Не ломай сохранённое состояние.** Оно лежит в `localStorage['pitradar.v1']`. `load()` сбрасывает всё, если `S.v !== 1`, поэтому не меняй `v` и `KEY` и не переименовывай поля `S`. Новые поля добавляй с дефолтом (как `S.cfg = {...DEF_CFG, ...S.cfg}`), чтобы старое состояние подхватилось.
  - Новые настройки — в `DEF_CFG`, они автоматически домёрджатся к сохранённым.

Синтаксическая проверка встроенного скрипта (нужен node):

```bash
node -e "const s=require('fs').readFileSync('index.html','utf8');const m=[...s.matchAll(/<script>([\s\S]*?)<\/script>/g)];new Function(m.map(x=>x[1]).join('\n'));console.log('ok')"
```

Если есть браузер — открыть страницу, Настройки → «Симуляция 5 ч», убедиться, что нет ошибок в консоли.

## Источник данных: Kart Chrono

- WebSocket `wss://kartchrono.com:9180`, клиент шлёт `{"trackId":"da5ce291c3fbb8feb31d79bdee1a00b7"}` (Стайки). Работает кросс-домен.
- Сначала JSON-снимок с `command:"clear"`, потом JSON-диффы; плюс бинарные пакеты `BINLAPS:` (круги по 52 байта).
- Коды полей взяты из `https://stayki.kartchrono.com/js/dataPullerWS2.js`. Подробности протокола — в `README.md`.
- Поля участника: 3 номер, 4 пилот, 5 состояние (6 PIT-IN, 7 PIT-OUT, 5 финиш), 10/11/12 последние круги, 13 круги, 26 команда, 27 число питов, 28 время пита, 62 PIT_LANE_SELECT.
- Поля гонки: 100 прошло (с), 101 осталось (с), 106 флаг (2 красный, 3 финиш, 4 разминка).
- Бинарная запись: cid@0, lapId@4, lapNum@8, raceLapNum@12, lapPos@16, s1–s3@20–28, lapTime@32, ts uint64 мс@36, flags@44, s4@48. Флаги: DELETED 0x100000, REJECTED 0x200000, PITIN 0x400000, PITOUT 0x800000.
- Для тестов на живых данных подходит любой трек Kart Chrono, например mayak `0a7e400059d7cea2bc8504c3788753c0`. Архив Стаек закрыт.

**Главная непроверенная вещь:** несёт ли поле 62 коридор A/B. Если да, разметка автоматическая (`autoLane`, `normLane()`); если нет, оператор жмёт A/B на каждый пит. Пользователь может прислать файл записи потока — по нему проверить, что приходит в `"62"`.

## Устройство `index.html`

Скрипт разбит на секции (заголовок-комментарий в начале `<script>`):

1. **Протокол** — `F`, `ST`, `FLAG`, `LF`, `KC_WS`, `STAYKI_TRACK`. Править здесь при смене формата.
2. **Состояние** — `DEF_CFG`, `fresh()`, `load()`, `save()` (троттлинг 1.5 с), `saveNow()` (не пишет во время Sim/Rep), `serverNow()`, `raceNow()`, `rtAt()`, `log()`. `Clock.virt` — виртуальное время для симуляции/реплея.
3. **Адаптер `KC`** — `connect/disconnect/handle`, `json()` (поля гонки, results/pitlane → `diff`), `diff(cid, d)` (пит по полю 5, запасной — по росту поля 27, коридор из 62, запасные круги по полю 13), `bin()`/`binRec()` (бинарные круги, пит по флагам круга, оценка смещения часов сервера).
4. **Движок**
   - `Eng`: `teamInfo`, `raceClock`, `addLap` (дедуп), `pitSignal` (дедуп 170 с; по счётчику — 360 с), `pitOut`, `laneSignal`, `setAutoLane` (ручной коридор приоритетнее авто).
   - `Act` — действия оператора: `lane`, `ignore`, `manualPit`, `move`, `remove`, `add`, `replace`, `undo`. Правки коридоров хранятся как относительные операции в `S.edits`.
   - `derive()` — **event sourcing**: питы и правки сортируются по времени и проигрываются в FIFO-коридоры. Пит кладёт карт команды в хвост коридора и выдаёт голову. Пит без коридора даёт заглушку `U<pitId>`. Результат в глобальном `D` (`lanes`, `teamKart`, `stints`, `kart`, `pitInfo`, `unassigned`), затем `metrics(D)`.
   - `metrics()`:
     - Эталон — скользящая медиана чистых кругов всех команд за `windowMin` минут.
     - Чистый круг: без плохих флагов, не у пита, не первый, в пределах ref×0.85 … ref×(1+cleanPct%).
     - Стинт идёт в зачёт при ≥ `minClean` чистых кругов. Поправка на команду — при ≥ 2 стинтах команды.
     - Рейтинг карта — взвешенно по числу чистых кругов. Цвета — перцентили (`greenPct`/`redPct`); при < 3 картах с данными все жёлтые.
5. **`Sim`** — мок-гонка 13 команд в формате протокола KC, со скрытой скоростью картов (`Sim.truth`), дождём и реальным FIFO. **`Rec`/`Rep`** — запись живого потока в файл и его реплей.
6. **UI**
   - Вкладки: `vPit` (пит-лейн, карточки питов `pitCard`, «Если заедем сейчас»), `vTrack` (стинты, «Скоро в пит» на 30/33 мин), `vKarts`, `vLog`, `vCfg`.
   - Модалки: `showSetup` (наша команда, число картов в A/B), `showKart`, `showTeam`.
   - Сигнал: `checkAlerts` + `alarm` (звук WebAudio, вибрация, вспышка) — только для чужих питов с зелёным картом.
   - Клики через делегирование `data-act` → объект `A`. Опасные действия подтверждаются в два нажатия (`twoStep`).
   - Главный цикл `loop()` раз в 200 мс; `derive()` вызывается, только когда `ui.dataDirty`.

Имена картов: `S<num>` — стартовый карт команды, `A1…/B1…` — стартовые в коридорах, `R…` — выданный на трассе, `N…` — добавленный вручную, `U<pitId>` (показывается как `?…`) — полученный в неразмеченном пите.

## Стиль кода

Плотный ванильный JS без фреймворков, короткие имена (`S`, `D`, `F`, `$`), комментарии по-русски и только там, где неочевидно. Тёмная тема, крупные кнопки под палец (телефон, перчатки, дождь). Держи этот стиль; не добавляй сборку, npm и новые файлы без явной просьбы.

## Второе приложение: `voice/` — «Голос круга»

`voice/index.html` → https://mixuigi.github.io/best-cart/voice/. Озвучивает в наушники время круга своего карта (по полю 3 NUM): время ×N повторов, «лучший», позиция, время лидера.

- Тот же протокол KC, но разбор только JSON (`results`/`pitlane`); круг ловится по изменению полей 13/10 с задержкой 700 мс, круги из снимка `clear` не озвучиваются.
- Фраза — список ключей фрагментов (`lapKeys`: 64326 → `f1 , z4 , n32` = «одна, ноль четыре, тридцать два»). Звучит нейроголос: mp3-фрагменты `voice/snd/<svetlana|dmitry|glados2>/<ключ>.mp3`, склейка через WebAudio (`Clips`). Фрагменты Светика и Димки генерирует `voice/make_clips.py` (edge-tts, тоже в venv `rutts`); новые слова добавлять в `PHR` в index.html и в `CLIPS` в скрипте одновременно. Системного голоса в списке нет, но если фрагменты ещё не загрузились — тем же текстом говорит системный TTS.
- Голоса (`VOICES`): «Светик» (`svetlana`), «Димка» (`dmitry`), «Гоночный инженер» (`radio` — фрагменты Димки + эффект рации), «GLaDOS» (`glados`). При выборе голос здоровается своим голосом (`hi` в `VOICES`, тексты в `HI`, объект `Greet`; у GLaDOS 4 фразы, одна и та же два раза подряд не выпадает). Фрагменты приветствий лежат только в папке своего голоса и грузятся первыми: `GREET` в make_clips.py, `HI` в make_glados2_clips.py.
- Kart Chrono сразу закрывает WebSocket, когда на треке нет активного заезда: это статус `idle`, не обрыв связи (переподключение раз в 10 с, голосом не сообщается).
- Работа при выключенном экране: зацикленный тихий шум (`Keep`) + Media Session; кнопка на наушниках повторяет последний круг. Надёжность фона на Android не гарантирована — если браузер засыпает, следующий шаг — нативное Android-приложение (foreground service + TextToSpeech).
- Настройки в `localStorage['lapvoice.v1']`.

## Android-обёртка `android/` (APK)

Зачем: Chrome на Android теряет мобильный интернет через 15–20 с после выключения экрана (на Wi-Fi работает), и страница в кармане замолкает. APK открывает ту же страницу `voice/` в WebView и держит фоновую службу `KeepAliveService` (foreground service типа mediaPlayback + partial wake lock + Wi-Fi lock) — так у процесса остаётся сеть.

- Логика остаётся на сайте: правки страницы приезжают в приложение через Pages, пересобирать APK не нужно.
- Мост JS → Android: `window.GolosApp` (`speak`, `stopSpeak`, `setStatus`). Системный голос в приложении идёт через Android TextToSpeech (в WebView нет Web Speech). Кнопки наушников ловит нативная MediaSession и зовёт `repeatLast()` на странице.
- Сборка — GitHub Actions `.github/workflows/apk.yml` при пуше в `android/**`; APK выкладывается в релиз `apk`: https://github.com/Mixuigi/best-cart/releases/download/apk/lap-voice.apk (приложение называется Lap Voice; applicationId прежний `by.mixuigi.golos`, чтобы ставилось поверх старых версий). При ошибке лог сборки уходит в релиз `apk-log` (`build-log.txt`) — его можно скачать без авторизации.
- Подпись: `android/app/sign.p12` (пароль в `app/build.gradle`) закоммичен намеренно, чтобы новые сборки ставились поверх старых. При изменениях поднимать `versionCode`.
- Запасной вариант без APK — «карманный режим» на странице: экран не гаснет (wake lock), но чёрный и игнорирует касания.

### Голос GLaDOS (`voice/`)

- Модель `TeraTTS/glados2-g2p-vits` из пакета RUTTS, без эффектов; синтез со своими параметрами: `lenght_scale` 0.826 (в 1.15 раза быстрее 0.95), шум 0.33/0.5 (у RUTTS зашиты 0.667/0.8; с ними «ноль» тянулся в «ноаль»). Оба значения пользователь выбрал на слух из сравнительных файлов — так и подбирать дальше. Фрагменты `snd/glados2/` генерирует `voice/make_glados2_clips.py` (~25 с на все), громкость выравнивается по Светлане. Окружение: `C:\Users\misha\venvs\rutts` (Python 3.11 — у RUTTS `transformers` 4.33 / `tokenizers` 0.13 без сборок под 3.12+), модель лежит в `C:\Users\misha\venvs\rutts-models` (по умолчанию RUTTS качает её в `./model`). В опции библиотеки `lenght_scale` опечатка — так и надо.
  - Ударения: у модели словарь на 2 млн слов (`exported/dictionary.txt`). RUTTS 0.1.13 открывает его без `encoding`, и на Windows (cp1251) не находит ни одного слова: все гласные безударные, «наль» вместо «ноль». Поэтому скрипт перезапускает себя с `-X utf8`; в venv `rutts` файл `RUTTS/tokenizer/g2p/tokenizer.py` исправлен вручную (`encoding="utf-8"`), после переустановки пакета правка пропадёт.
  - У омографов словарь берёт последнюю строку: «шесть» → «шёсть», «две» → «двё», «не» → «нё», «пятьдесят» → «писят». Правки — в `WORDS` (слово везде) и `STRESS` (фраза целиком) через `+` перед ударной гласной (`прив+ет`); слово с `+` идёт мимо словаря. Проверка без синтеза: `--check` печатает фонемы (`o1` ударная, `o0` безударная), затем `--force`.
- Прежняя GLaDOS (Светлана + своя обработка `glados_style.py`, зал `hallChain`) удалена по просьбе пользователя: готовая модель звучит лучше. Код — в истории git до коммита с её удалением.

Новые фразы: добавить в `PHR` (index.html) и `CLIPS` (make_clips.py), затем запустить оба генератора (make_clips, make_glados2_clips) — они досоздают только недостающие фрагменты.

Паузы внутри фразы: `[0.4]` в тексте (оба генератора) — части озвучиваются отдельно и склеиваются через паузу ровно в 0.4 с; так поправлены пауза после тире у GLaDOS и слишком длинные (~1.1 с) паузы edge-tts после «Привет!»/«Здравствуй!». `make_glados2_clips.py <ключ> …` пересоздаёт только указанные фрагменты: у модели случайный шум, и `--force` слегка меняет все уже одобренные.

Фразы GLaDOS для езды — `RIDE` в make_glados2_clips.py (ключи `gl_*`, только у GLaDOS). Когда они звучат, пользователь напишет позже; в index.html они пока не подключены. Подключать по образцу «приколдесов»: условие → ключ → проверка в симуляторе.

Claude Code в desktop-приложении на Windows работает в MSIX-контейнере: всё, что он пишет в `AppData`, попадает в виртуальную копию и не видно из обычного терминала. Python-окружения для пользователя ставить вне `AppData` (`uv` с `UV_PYTHON_INSTALL_DIR=C:\Users\misha\venvs\.python`).

«Приколдесы» (настройка `sayTaunt`) — фразы за серию кругов подряд на позициях: таблица `STREAKS` в voice/index.html (`pos:[от, до]`, `laps`, `say`, опц. `once`), счёт — объект `Streak`. Серия рвётся кругом вне позиций, пропуском номера круга (обрыв связи) и сменой заезда/карта; переподключение без пропуска кругов её не рвёт. Одна фраза за серию; на одном круге — одна фраза (первое правило в списке, узкие выше). Сейчас одно правило: «Я запишу в свой отчёт твои результаты… Их никто не увидит» (`report1`/`report2`) на 5-м круге подряд на 6-м месте и дальше (6, 7, 8…; `pos:[6, Infinity]`). Звучат только голосом с `taunts:true` в `VOICES` (сейчас GLaDOS) и только его фрагментами: пока они грузятся или выбран другой/системный голос — молчат (`tauntOff()`, причина видна в логе симулятора). Фрагменты новых фраз всё равно генерировать для всех голосов: `Clips.ready` требует все ключи `PHR`. Осторожно с формулировками: «6-е и выше» в просьбах пользователя значит номера 6, 7, 8…, а не топ-6.

Симулятор заезда (`Sim`, карточка внизу страницы) гонит фейковый заезд через настоящий `KC.json` → `diff` → `lap` → `Streak` → `announce` и пишет в лог каждый круг: позицию, счёт серий и полный текст фразы. План: `13*10` — 10 кругов на 13-м месте, `x` — круг без связи, `r` — переподключение; пусто — случайные позиции без конца. «1 с» — без голоса, «20 с» — тест в кармане. Новые приколдесы проверять на нём.
