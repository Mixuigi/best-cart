# Пит-радар + Голос круга — контекст для Claude Code

Отвечай пользователю по-русски. Интерфейс обоих приложений тоже на русском.

## Карта репозитория

Два независимых веб-приложения для картинга на live-тайминге Kart Chrono плюс Android-обёртка ко второму. Сборки нет: чистый HTML/JS, хостинг — GitHub Pages из `main`.

| Путь | Что это |
|---|---|
| `index.html` | **Пит-радар** — трекер картов в пит-лейне для командного марафона. Один файл. https://mixuigi.github.io/best-cart/ |
| `README.md` | Пит-радар: инструкция пользователя и протокол Kart Chrono |
| `voice/index.html` | **Голос круга** — озвучивает в наушники время круга своего карта. Один файл. https://mixuigi.github.io/best-cart/voice/ |
| `voice/snd/<голос>/<ключ>.mp3` | Готовые фрагменты озвучки (svetlana, dmitry, glados2) — коммитятся |
| `voice/make_clips.py` | Генератор фрагментов Светика и Димки (edge-tts) и общий список текстов `CLIPS` |
| `voice/make_glados2_clips.py` | Генератор фрагментов GLaDOS (модель RUTTS) + её личные фразы `HI`, `RIDE` |
| `voice/requirements.txt` | Пакеты для генераторов (Python 3.11) |
| `android/` | APK «Lap Voice» — WebView с `voice/` + фоновая служба. Собирает GitHub Actions |
| `.github/workflows/apk.yml` | Сборка APK в релиз `apk`: https://github.com/Mixuigi/best-cart/releases/download/apk/lap-voice.apk |
| `.claude/launch.json` | Локальный сервер `voice` для превью в Claude Desktop |

## Как работаем с пользователем

- Пользователь гоняет на картинге и правит приложения с телефона в том числе **прямо во время заездов**. Маленькие точечные коммиты, сразу пуш в `main`, без PR (если не попросит иное). Пуш → через ~1 мин обновляется на телефоне и в APK.
- Перед пушем — синтаксическая проверка страницы (ниже). Сломанный JS посреди гонки = белый экран.
- **Озвучку пользователь выбирает на слух.** Не угадывать: собрать WAV с пронумерованными вариантами (перед каждым голос сам говорит «Вариант один…»), прислать, дождаться номера. Файлы сравнения — вне репозитория (например, в `../voice-samples/`). Одобренный вариант класть в `snd/` **ровно тем звуком**, что он слышал (синтез каждый раз чуть другой), а текст с правками ударений — в генератор.
- Осторожно с позициями: «6-е и выше» у пользователя значит места 6, 7, 8… (номер больше), а не топ-6.
- Перед заливкой новых фраз — прислать их послушать; заливать после «ок».

## Новый компьютер: настройка

```bash
git clone https://github.com/Mixuigi/best-cart.git && cd best-cart
```

**Превью.** Страницу открывать по http, не `file://` (иначе `fetch` фрагментов озвучки не работает):

```bash
python -m http.server 8765 --bind 127.0.0.1
```

Потом http://localhost:8765/voice/ (или `/` для пит-радара). В Claude Desktop это конфигурация `voice` в `.claude/launch.json`.

**Синтаксическая проверка** обоих приложений (нужен node; если его нет — открыть страницу в браузере и смотреть консоль):

```bash
node -e "for(const f of ['index.html','voice/index.html']){const s=require('fs').readFileSync(f,'utf8');new Function([...s.matchAll(/<script>([\s\S]*?)<\/script>/g)].map(x=>x[1]).join('\n'))}console.log('ok')"
```

**Окружение для генерации озвучки** — нужно только если добавляешь/меняешь фразы. Строго Python 3.11 (RUTTS тянет `tokenizers` 0.13.3 без сборок под 3.12+; под 3.15 нет `onnxruntime`). Удобнее всего через `uv`, он сам скачает 3.11:

```bash
python -m pip install --user uv
python -m uv venv --python 3.11 ~/venvs/rutts
python -m uv pip install --python ~/venvs/rutts -r voice/requirements.txt
```

- Запуск: `~/venvs/rutts/Scripts/python voice/make_clips.py` и `… voice/make_glados2_clips.py` (на Linux/macOS — `bin/python`).
- Модель GLaDOS (~120 МБ) скачается при первом запуске в `~/venvs/rutts-models` (переопределить — `RUTTS_MODELS`).
- **Windows + Claude Desktop:** он работает в MSIX-контейнере — всё, что пишется в `AppData`, попадает в его виртуальную копию и не видно из обычного терминала (и `uv` путается со ссылками на Python). Ставить Python вне `AppData`: перед `uv venv` задать `UV_PYTHON_INSTALL_DIR=~/venvs/.python`. Если `python -m pip install --user uv` поставил `uv.exe` в `AppData\Roaming\Python\…\Scripts`, звать его по полному пути.
- **Windows + RUTTS:** библиотека открывает словарь ударений без `encoding`, на cp1251 не находит ни одного слова → все гласные безударные («наль» вместо «ноль»). `make_glados2_clips.py` сам перезапускается с `python -X utf8`; свои скрипты с RUTTS тоже запускать с `-X utf8` (или поправить `RUTTS/tokenizer/g2p/tokenizer.py`: `open(..., encoding="utf-8")` в двух местах).

**APK** собирается в GitHub Actions при пуше в `android/**` — Android SDK локально не нужен.

# Пит-радар (`index.html`)

## Суть

Браузерное приложение для командного картингового марафона на Стайках (Минск): 5 ч, 11:00–16:00, трек 1233 м, круг ~1:04–1:08 на сухом, ~1:14 в дождь. Оператор смотрит его с телефона в боксах.

Задача — знать, какие физические карты быстрые, и видеть, когда быстрый карт уходит в пит-лейн, чтобы заехать за ним.

Регламент, на котором держится логика:
- Номер команды = транспондер, не карт. Карт команды меняется на каждом пите.
- 15 обязательных питов, стинт ≤ 35 мин (от PIT IN до PIT IN), пит ≥ 2 мин, первый пит не раньше 10 мин.
- После PIT IN софт случайно назначает коридор A или B. Команда ставит свой карт в хвост коридора и берёт ПЕРВЫЙ карт этого коридора. Это строгий FIFO постоянной длины.
- При поломке запасной карт выдают на трассе. Красный флаг останавливает время гонки.

## Деплой и состояние

- Один файл, без сборки, зависимости только с CDN (SortableJS 1.15.0 с cdnjs, шрифт Roboto Condensed с Google Fonts).
- **Не ломай сохранённое состояние.** Оно лежит в `localStorage['pitradar.v1']`. `load()` сбрасывает всё, если `S.v !== 1`, поэтому не меняй `v` и `KEY` и не переименовывай поля `S`. Новые поля добавляй с дефолтом (как `S.cfg = {...DEF_CFG, ...S.cfg}`), чтобы старое состояние подхватилось. Новые настройки — в `DEF_CFG`.
- Проверка в браузере: Настройки → «Симуляция 5 ч», в консоли нет ошибок.

## Источник данных: Kart Chrono

- WebSocket `wss://kartchrono.com:9180`, клиент шлёт `{"trackId":"da5ce291c3fbb8feb31d79bdee1a00b7"}` (Стайки). Работает кросс-домен. Все 55 трасс Kart Chrono (kartchrono.com/tracks.php) — тот же сервер и формат.
- Сначала JSON-снимок с `command:"clear"`, потом JSON-диффы; плюс бинарные пакеты `BINLAPS:` (круги по 52 байта). Если на трассе нет активного заезда, сервер сразу закрывает соединение.
- Коды полей взяты из `https://stayki.kartchrono.com/js/dataPullerWS2.js`. Подробности протокола — в `README.md`.
- Поля участника: 1 позиция, 3 номер, 4 пилот, 5 состояние (6 PIT-IN, 7 PIT-OUT, 5 финиш), 6 лучший, 10/11/12 последние круги, 13 круги, 14 отставание (>0 — мс, от −1 до −9999 — круги), 26 команда, 27 число питов, 28 время пита, 62 PIT_LANE_SELECT.
- Поля заезда: 100 прошло (с), 101 осталось (с), 102 всего кругов, 103 осталось кругов, 104 заезд, 105 гонка, 106 флаг (2 красный, 3 финиш, 4 разминка), 108 тип финиша (finishByTime / finishByLaps / extraLaps), 111 GUID заезда.
- Бинарная запись: cid@0, lapId@4, lapNum@8, raceLapNum@12, lapPos@16, s1–s3@20–28, lapTime@32, ts uint64 мс@36, flags@44, s4@48. Флаги: DELETED 0x100000, REJECTED 0x200000, PITIN 0x400000, PITOUT 0x800000.
- Для тестов на живых данных подходит любой трек Kart Chrono, например mayak `0a7e400059d7cea2bc8504c3788753c0`. Архив Стаек закрыт.

**Главная непроверенная вещь:** несёт ли поле 62 коридор A/B. Если да, разметка автоматическая (`autoLane`, `normLane()`); если нет, оператор жмёт A/B на каждый пит. Пользователь может прислать файл записи потока — по нему проверить, что приходит в `"62"`.

## Устройство `index.html`

Скрипт разбит на секции (заголовок-комментарий в начале `<script>`):

1. **Протокол** — `F`, `ST`, `FLAG`, `LF`, `KC_WS`, `STAYKI_TRACK`. Править здесь при смене формата.
2. **Состояние** — `DEF_CFG`, `fresh()`, `load()`, `save()` (троттлинг 1.5 с), `saveNow()` (не пишет во время Sim/Rep), `serverNow()`, `raceNow()`, `rtAt()`, `log()`. `Clock.virt` — виртуальное время для симуляции/реплея.
3. **Адаптер `KC`** — `connect/disconnect/handle`, `json()` (поля гонки, results/pitlane → `diff`), `diff(cid, d)` (пит по полю 5, запасной — по росту поля 27, коридор из 62, запасные круги по полю 13), `bin()`/`binRec()` (бинарные круги, пит по флагам круга, оценка смещения часов сервера).
4. **Движок**
   - `Eng`: `teamInfo`, `raceClock`, `addLap` (дедуп), `pitSignal` (дедуп 170 с; по счётчику — 360 с), `pitOut`, `laneSignal`, `setAutoLane` (ручной коридор приоритетнее авто).
   - `Act` — действия оператора: `lane`, `ignore`, `manualPit`, `move`, `remove`, `add`, `replace`, `undo`. Правки коридоров хранятся как относительные операции в `S.edits`.
   - `derive()` — **event sourcing**: питы и правки сортируются по времени и проигрываются в FIFO-коридоры. Пит кладёт карт команды в хвост коридора и выдаёт голову. Пит без коридора даёт заглушку `U<pitId>`. Результат в глобальном `D` (`lanes`, `teamKart`, `stints`, `kart`, `pitInfo`, `unassigned`), затем `metrics(D)`.
   - `metrics()`:
     - Эталон — скользящая медиана чистых кругов всех команд за `windowMin` минут.
     - Чистый круг: без плохих флагов, не у пита, не первый, в пределах ref×0.85 … ref×(1+cleanPct%).
     - Стинт идёт в зачёт при ≥ `minClean` чистых кругов. Поправка на команду — при ≥ 2 стинтах команды.
     - Рейтинг карта — взвешенно по числу чистых кругов. Цвета — перцентили (`greenPct`/`redPct`); при < 3 картах с данными все жёлтые.
5. **`Sim`** — мок-гонка 13 команд в формате протокола KC, со скрытой скоростью картов (`Sim.truth`), дождём и реальным FIFO. **`Rec`/`Rep`** — запись живого потока в файл и его реплей.
6. **UI**
   - Вкладки: `vPit` (пит-лейн, карточки питов `pitCard`, «Если заедем сейчас»), `vTrack` (стинты, «Скоро в пит» на 30/33 мин), `vKarts`, `vLog`, `vCfg`.
   - Модалки: `showSetup` (наша команда, число картов в A/B), `showKart`, `showTeam`.
   - Сигнал: `checkAlerts` + `alarm` (звук WebAudio, вибрация, вспышка) — только для чужих питов с зелёным картом.
   - Клики через делегирование `data-act` → объект `A`. Опасные действия подтверждаются в два нажатия (`twoStep`).
   - Главный цикл `loop()` раз в 200 мс; `derive()` вызывается, только когда `ui.dataDirty`.

Имена картов: `S<num>` — стартовый карт команды, `A1…/B1…` — стартовые в коридорах, `R…` — выданный на трассе, `N…` — добавленный вручную, `U<pitId>` (показывается как `?…`) — полученный в неразмеченном пите.

## Стиль кода (оба приложения)

Плотный ванильный JS без фреймворков, короткие имена (`S`, `D`, `F`, `$`), комментарии по-русски и только там, где неочевидно. Тёмная тема, крупные кнопки под палец (телефон, перчатки, дождь). Держи этот стиль; не добавляй сборку, npm и новые файлы без явной просьбы.

# Голос круга (`voice/`)

Озвучивает в наушники время круга своего карта (по полю 3 NUM): время ×N повторов, «Твой лучший круг!», позиция, отставание, время лидера; на старте — «Слежу за картом N». Экран можно выключить (см. Android-обёртку). Настройки — `localStorage['lapvoice.v1']`, новые поля — с дефолтом в `DEF`.

## Как устроено

- **Тайминг:** тот же KC, но разбор только JSON (`results`/`pitlane`). Круг ловится по изменению полей 13/10 с задержкой 700 мс (`KC.timer`), круги из снимка `clear` не озвучиваются. Закрытие сокета без данных — статус `idle` («заезда нет»), не обрыв; переподключение раз в 10 с. Сверху — название заезда и оставшееся время (`runClock`), есть табло всех картов и толерантный поиск по 55 трассам (`TRACKS`, `searchTracks`).
- **Фраза** — список ключей фрагментов: `n0..n99` числа, `z0..z9` «ноль N», `f1/f2` «одна/две», слова из `PHR`; `','` — пауза 0.1 с, `'.'` — 0.45 с, число — пауза в секундах. `lapKeys(64326)` → `f1 , z4 , n32` = «одна, ноль четыре, тридцать два».
- **`Clips`** — склейка mp3-фрагментов через WebAudio по расписанию; каждый источник регистрируется (`track`), `cancel()` глушит все запланированные (раньше был `ctx.suspend()` — фразы доигрывали поверх следующих). `Clips.ready` = загружены **все** `CLIP_KEYS` (числа + `PHR`), поэтому фрагмент нового слова из `PHR` нужен в папке каждого голоса. Пока не загрузились — говорит системный TTS тем же текстом (`keyText`). Загрузка по 6 параллельно, 3 попытки, повтор через 15 с.
- **Громкость:** ползунок до 400 % — `master()`: усиление → лимитер → мягкий срез (нужно, когда Discord переводит телефон в режим звонка). В APK есть кнопка «громкость медиа на максимум».
- **`Sample`** — тест голоса и превью громкости: пока пробная фраза звучит, повторные нажатия игнорируются.
- **Голоса (`VOICES`):** «Светик» (`svetlana`), «Димка» (`dmitry`), «Гоночный инженер» (`radio` — фрагменты Димки + эффект рации `radioChain`/`radioClick`), «GLaDOS» (`glados`, папка `glados2`, `taunts:true`). Системного голоса в списке нет (сохранённый системный → Светик).
  - `hi` — приветствие при выборе голоса его же голосом (`Greet`, ждёт загрузки фрагмента до 20 с; у GLaDOS 4 фразы, `pick` не даёт одну и ту же два раза подряд). Тексты — `HI`.
  - `start` (только GLaDOS) — после «Слежу за картом N» пауза ~1 с и случайная фраза: `gl_helmet`, `gl_bones`, `gl_count`, `gl_turn`, `gl_trial`. Тексты фраз GLaDOS — `GL`.
  - Свои фрагменты голоса (`hi`/`start`) лежат только в его папке и грузятся первыми.
- **«Приколдесы»** (`sayTaunt`, по умолчанию вкл) — все дополнительные фразы GLaDOS на старте и на трассе. Галочка видна только у голоса с `taunts:true`; звучат только его фрагментами (`tauntOff()` — причина молчания, видна в логе симулятора). Приветствия при выборе голоса от галочки не зависят.
  - Серии кругов — таблица `STREAKS` (`pos:[от, до]`, `laps`, `say`, опц. `once`), счёт — `Streak`. Серия рвётся кругом вне позиций, пропуском номера круга (обрыв связи) и сменой заезда/карта; переподключение без пропуска кругов не рвёт. Одна фраза за серию; на одном круге — одна (первое правило в списке, узкие выше).
  - Сейчас одно правило: «Я запишу в свой отчёт твои результаты… Их никто не увидит» (`report1`/`report2`) на 5-м круге подряд на 6-м месте и дальше (`pos:[6, Infinity]`).
- **Симулятор заезда** (`Sim`, карточка внизу страницы) гонит фейковый заезд через настоящий `KC.json` → `diff` → `lap` → `Streak` → `announce` и пишет в лог каждый круг: позицию, счёт серий и полный текст фразы. План: `13*10` — 10 кругов на 13-м месте, `x` — круг без связи, `r` — переподключение; пусто — случайные позиции. «1 с» — без голоса, «20 с» — тест в кармане. Новые приколдесы проверять на нём.
- **Карманный режим** — экран не гаснет (wake lock), но чёрный и игнорирует касания; выход — удержание 3 с. Фон в браузере держит тихий шум (`Keep`) + Media Session; кнопка на наушниках повторяет последний круг.

## Озвучка: генераторы

Новая фраза для всех голосов: текст в `PHR` (index.html) и в `CLIPS` (make_clips.py), затем оба генератора — они досоздают только недостающие фрагменты. Личные фразы GLaDOS — в `HI`/`RIDE` make_glados2_clips.py и в `HI`/`GL` + `VOICES.glados` в index.html.

- **`make_clips.py`** — edge-tts, `ru-RU-SvetlanaNeural` / `ru-RU-DmitryNeural`, rate +5 %. Приветствия — `GREET` (только в папке своего голоса). Edge-tts держит после «!» ~1.1 с — укорочено разметкой `[0.36]`/`[0.4]` до 0.5 с. «Менеджер» Дмитрий читал без «р» (как английское слово) — поэтому написано «мэнэджер».
- **`make_glados2_clips.py`** — модель `TeraTTS/glados2-g2p-vits` (RUTTS), без эффектов. Свои параметры синтеза: `lenght_scale` 0.826 (в 1.15 раза быстрее 0.95; опечатка в имени — из библиотеки), шум 0.33/0.5 (у RUTTS зашиты 0.667/0.8, с ними «ноль» тянулся в «ноаль»). Оба значения пользователь выбрал на слух. Громкость выравнивается по Светлане (`TARGET_RMS`).
  - `--check [ключ …]` — фонемы без синтеза (`o1` ударная, `o0` безударная); `ключ …` — пересоздать только эти фрагменты; `--force` — все (не нужно без причины: у модели случайный шум, уже одобренные слегка изменятся).
  - Ударения: у модели словарь на 2 млн слов, у омографов берётся последняя строка — «шесть» → «шёсть», «две» → «двё», «не» → «нё», «все» → «всё», «готов» → «г+отов», «пятьдесят» → «писят»; предлоги «за», «на», «из», «у» — ударные. Правки — `WORDS` (слово везде) и `STRESS` (фраза целиком) через `+` перед ударной гласной; слово с `+` идёт мимо словаря. Безударное «не»/предлог — писать слитно со следующим словом (`неув+идит`, `зак+артом`). Латиницу модель не читает (`Гл+адос`).
  - Модель глотает звуки: помогает удвоить букву (`т+оррт`, `почтт+и`, `п+уннкта`, `ре+акциюю,`) или поставить запятую после слова (`теп+ерь,`).
  - `RIDE` синтезируется `SMOOTH` = 8 раз, берётся прогон с самым ровным тоном (`jump`): у модели бывают «вскрики» — скачок тона на октаву.
- **Паузы внутри фразы** (оба генератора): `[0.4]` в тексте — части озвучиваются отдельно и склеиваются через паузу; слышимая пауза выходит на ~0.1 с длиннее числа — проверять замером.

## Android-обёртка `android/` (APK «Lap Voice»)

Зачем: Chrome на Android теряет мобильный интернет через 15–20 с после выключения экрана (на Wi-Fi работает), и страница в кармане замолкает. APK открывает ту же страницу `voice/` в WebView и держит фоновую службу `KeepAliveService` (foreground service типа mediaPlayback + partial wake lock + Wi-Fi lock) — так у процесса остаётся сеть. WebView переопределяет `onWindowVisibilityChanged` (всегда VISIBLE), чтобы Chromium не тормозил таймеры.

- Логика остаётся на сайте: правки страницы приезжают в приложение через Pages (страница грузится с `?v=время`), пересобирать APK не нужно.
- Мост JS → Android: `window.GolosApp` (`speak`, `stopSpeak`, `setStatus`, `maxVolume`). Системный голос в приложении — Android TextToSpeech (в WebView нет Web Speech). Кнопки наушников ловит нативная MediaSession и зовёт `repeatLast()` на странице.
- Сборка — `.github/workflows/apk.yml` при пуше в `android/**`; APK — в релиз `apk` (`lap-voice.apk`). applicationId прежний `by.mixuigi.golos`, чтобы ставилось поверх старых версий. При ошибке лог сборки уходит в релиз `apk-log` (`build-log.txt`), его можно скачать без авторизации.
- Подпись: `android/app/sign.p12` (пароль в `app/build.gradle`) закоммичен намеренно, чтобы новые сборки ставились поверх старых. При изменениях поднимать `versionCode` (сейчас 4, версия 1.3).
